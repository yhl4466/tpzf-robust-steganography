人工验收清单（自动化测不了的部分，请手动逐项确认）
  1. 打开 index.html → 点击"去嵌入""去提取"两个大按钮，确认跳转正确； 三张特性卡、"怎么用"三步、两处黄色警告区与"常见问题（FAQ）"折叠面板都正常显示， 展开 FAQ 的五条问答，确认页脚 GitHub 占位符与 GPL-3.0 协议说明在位。
  2. 打开 embed.html → 上传一张纹理丰富的载体图（≥512×512）与一张秘密图，观察： 状态提示是否在"上传两张图后可开始 / 秘密图偏大，将自动缩小至 W×H / 已就绪"之间正确切换； 点击"开始嵌入"后进度条是否推进；完成后是否出现隐写图预览、自然语言统计与"下载隐写图"； 展开"高级设置"切换抗损坏档位与抗缩放模式，确认文字说明随之变化（三档文案应为 "稳定抗 25~35% / 15~25% / 10~15%"，不要再用旧的等分面积表述）； 确认结果区出现"⚠️ 推荐传输方式（决定对方能不能还原）"折叠说明，且分享提示里带 "必须通过'原图/文件'方式传输"的警告； 再换一张"大片平滑天空 + 少量细纹"的图，确认提示里出现"已避开 N 个过于平滑的区域" （这些区域单独承载数据时扛不住压缩，工具不会把数据放进去）； 最后点第 4 步"遮住 10% / 25% / 40% / 50% 再试"，确认右侧出现被涂黑的对比图、状态行给出 "模拟损坏 X%：提取成功，用时 Y 秒"（或"读出 N/K 个数据块"），且下载的隐写图未被改动。
  3. 打开 extract.html → 上传刚刚下载的 stego.png，确认： 提取成功（绿底提示）、秘密图预览与"用时 YY 秒"；展开"查看诊断详情"，确认方块校验图以绿色为主， 且"常规提取"一行同时给出 6 对模式与 4 对低频模式的读数（成功时会注明"未再试 4 对低频模式"）； 点击"下载秘密图"能保存（预览即使不可用也必须能下载：预览失败时提示应为 "数据已还原，但预览不可用，请直接下载"，而不是抛出 getImageData 之类的技术错误）； 再上传一张未隐写的图片，确认显示红底友好提示而非报错， 且状态行仍带真实读数（"常规提取 0/K 块…未检测到标尺"），不会只显示一个 0。
  4. 打开 tech.html → 确认学术论文体：摘要 / Abstract / 关键词 / 参考文献齐全， 9 章结构与本报告一致，6 幅字符图与 8 张编号表正常显示， "传输信道要求"一节给出微信原图与普通发送的对照，§7.1 有 T30 已知限制说明， 底部回到首页与开发者测试页的链接可用。
  5. 打开 dev-test-suite.html → 点击"开始全部测试"，观察结果表格逐行实时更新、分组筛选可用、底部统计正确； 对失败项（若有）展开备注查看具体数字。
  6. 打开 test-image-utils.html 与 test-stego-pipeline.html（开发工具页），确认仍可正常运行： 前者能上传图片并显示方差绿/红框；后者能完成一次嵌入与提取闭环。
  7. 断网后再打开以上页面，确认全部功能不受影响（零外部依赖、无 CDN）。
测试全部在浏览器本地运行，不上传任何数据。缩放与 JPEG 重编码使用浏览器原生 Canvas，结果与实机一致。
